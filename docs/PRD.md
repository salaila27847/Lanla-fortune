# PRD — เว็บแอปดูดวง 3 ศาสตร์ (Uranian × Tarot × Oracle)

## 1. เป้าหมาย

สร้างเว็บแอปที่ผสาน**โหราศาสตร์ยูเรเนียน**, **ไพ่ทาโรต์**, และ **ไพ่ออราเคิล** เข้าด้วยกันแบบสมบูรณ์ (ไม่ใช่แค่แสดงผลแยกกัน) โดยมีชั้นตีความกลาง ("หัวหน้าทีมหลัก") ที่วิเคราะห์ไขว้ผลลัพธ์จากทั้ง 3 ศาสตร์อย่างมืออาชีพ ไม่มี bias ส่วนตัว และไม่ใช้ประวัติผู้ใช้มาปรุงแต่งคำทำนาย

## 2. ผู้ใช้เป้าหมาย

ผู้ที่สนใจศาสตร์การพยากรณ์ ต้องการคำทำนายที่มองจากหลายมุมพร้อมกันในคำถามเดียว (เช่น เรื่องการงาน ความรัก การเงิน)

## 3. User flow หลัก

1. ผู้ใช้กรอกข้อมูลเกิด (วัน เดือน ปี เวลา สถานที่เกิด — สำหรับคำนวณยูเรเนียน)
2. ผู้ใช้ตั้งคำถามหรือเลือกหมวดคำถาม (การงาน/ความรัก/การเงิน/ทั่วไป)
3. ผู้ใช้จั่วไพ่ทาโรต์ (เช่น 3 ใบ หรือ Celtic Cross) ผ่าน UI แบบ interactive
4. ผู้ใช้จั่วไพ่ออราเคิล 1 ใบ (หรือตามชุดที่กำหนด)
5. ระบบส่งข้อมูลทั้งหมดไปยัง 3 engine พร้อมกัน
6. Master Interpreter รับผลดิบจากทั้ง 3 engine มาสังเคราะห์
7. แสดงผลคำทำนายฉบับสมบูรณ์ พร้อมรายละเอียดแยกแต่ละศาสตร์ (ให้ผู้ใช้ดูที่มาได้)

## 4. ฟังก์ชันของแต่ละโมดูล

### 4.1 Uranian Engine
- คำนวณตำแหน่งดาว 8 ดวงเสริม (Cupido, Hades, Zeus, Kronos, Apollon, Admetos, Vulcanus, Poseidon) และดาวหลัก
- คำนวณ midpoint และตำแหน่งบน 90° dial
- จับคู่ configuration กับฐานความหมายใน knowledge base
- Input: วันเวลาสถานที่เกิด + วันเวลาปัจจุบัน (transit)
- Output: `EngineResult` (ดู data-schema.md)

### 4.2 Tarot Engine
- สุ่มจั่วไพ่แบบ fair-random (ไม่ซ้ำใบในกองเดียวกัน)
- รองรับหลาย spread (3 ใบ, Celtic Cross เป็นต้น)
- จับคู่ไพ่ + ตำแหน่งใน spread กับความหมายในฐานข้อมูล (อ้างอิงไฟล์ที่มีอยู่แล้วจากโปรเจกต์ Destiny Matrix — ตรวจสอบว่ามีไฟล์อ้างอิงความหมาย 22 เลข/Major Arcana หรือไม่ก่อนสร้างใหม่)
- Output: `EngineResult`

### 4.3 Oracle Engine
- สุ่มจั่วไพ่จากชุดออราเคิลที่กำหนด (เลือกชุดในเฟสถัดไป — ยังไม่ตัดสินใจ)
- จับคู่ไพ่กับข้อความ/ธีมในฐานข้อมูล
- Output: `EngineResult`

### 4.4 Master Interpreter (Synthesis Layer)
- รับ `EngineResult` จากทั้ง 3 engine
- เรียก Gemini API (`gemini-3.5-flash`) พร้อม prompt ที่ระบุกฎตายตัว:
  - ห้ามใส่ bias ส่วนตัว
  - ห้ามอ้างอิงข้อมูลนอกเหนือจากที่ส่งเข้าไปในเซสชันนี้
  - ต้องทำ 3 ขั้นตอน: หาจุดร่วม (convergence) → จัดการความขัดแย้ง (divergence) → เติมเต็มมุมที่ขาด (complementary)
- Output: คำทำนายฉบับสมบูรณ์ + คำอธิบายว่าแต่ละศาสตร์สนับสนุนข้อสรุปอย่างไร

## 5. Non-functional requirements

- ความถูกต้องของการคำนวณยูเรเนียน/สุ่มไพ่ ต้องมี unit test ครอบคลุม
- Privacy: ไม่เก็บ/ไม่ใช้ browsing history ของผู้ใช้ในการตีความ
- Performance: การเรียก 3 engine ควรทำแบบ concurrent (async) ไม่ใช่ sequential
- Extensibility: เพิ่มชุดไพ่ออราเคิลใหม่ หรือปรับฐานความหมายได้โดยแก้ knowledge base ไม่ต้องแก้โค้ด

## 6. Out of scope (เฟสนี้)

- ระบบสมาชิก/ล็อกอิน
- การชำระเงิน
- แอปมือถือ native
