# PRD — เว็บแอปดูดวง 3 ศาสตร์ (Uranian × Tarot × Oracle)

## 1. เป้าหมาย

สร้างเว็บแอปที่ผสาน**โหราศาสตร์ยูเรเนียน**, **ไพ่ทาโรต์**, และ **ไพ่ออราเคิล** เข้าด้วยกันแบบสมบูรณ์ (ไม่ใช่แค่แสดงผลแยกกัน) โดยมีชั้นตีความกลาง ("หัวหน้าทีมหลัก") ที่วิเคราะห์ไขว้ผลลัพธ์จากทั้ง 3 ศาสตร์อย่างมืออาชีพ ไม่มี bias ส่วนตัว และไม่ใช้ประวัติผู้ใช้มาปรุงแต่งคำทำนาย

## 2. ผู้ใช้เป้าหมาย

ผู้ที่สนใจศาสตร์การพยากรณ์ ต้องการคำทำนายที่มองจากหลายมุมพร้อมกันในคำถามเดียว (เช่น เรื่องการงาน ความรัก การเงิน)

## 3. User flow หลัก

**แก้ไข 2026-08-14**: ผู้ใช้ไม่ถูกบังคับให้ใช้ครบทั้ง 3 ศาสตร์อีกต่อไป — แต่ละขั้นตอนมีปุ่มข้าม
("ข้ามยูเรเนียน" / "ข้ามไพ่ทาโรต์" / "ข้ามไพ่ออราเคิล") ใช้ 1 หรือ 2 ใน 3 ศาสตร์ก็ได้ (ระบบบังคับแค่
ต้องเหลืออย่างน้อย 1 ศาสตร์เสมอ — ปุ่มข้ามไพ่ออราเคิลจะไม่แสดงถ้าข้ามอีก 2 ศาสตร์ไปแล้ว)

0. ผู้ใช้ล็อกอินด้วย Google (บังคับก่อนใช้ `/reading`/`/history`)
1. ผู้ใช้กรอกข้อมูลเกิด (วัน เดือน ปี เวลา สถานที่เกิด — สำหรับคำนวณยูเรเนียน) และเลือกเปิด/ปิด
   forecast เสริมที่ต้องการ (Solar Arc/Transit/Lunar Return/Relocation — ไม่บังคับ, checkbox ต่อตัว
   เปิดฟิลด์ของตัวเองเมื่อติ๊ก) หรือกด **ข้ามยูเรเนียน** เพื่อไม่กรอกข้อมูลเกิดเลย
2. ผู้ใช้เลือกเลย์เอาท์ไพ่ทาโรต์จากตัวเลือกที่หลากหลาย (ไพ่ใบเดียว, อดีต-ปัจจุบัน-อนาคต,
   สถานการณ์-อุปสรรค-คำแนะนำ, ความสัมพันธ์ 5 ใบ, กากบาทเซลติก 10 ใบ) แล้วจั่วไพ่ตามตำแหน่งของ
   เลย์เอาท์นั้นผ่าน UI แบบ interactive หรือกด **ข้ามไพ่ทาโรต์**
3. ไพ่ออราเคิล — จำนวนใบที่จั่วสุ่มจากระบบเสมอ (3-9 ใบ ไม่ให้ผู้ใช้เลือกเอง):
   - ถ้าข้ามทั้งยูเรเนียนและทาโรต์มาก่อน (ใช้ออราเคิลศาสตร์เดียว) ผู้ใช้ต้อง **พิมพ์คำถามก่อน**
     ระบบถึงจะสุ่มจำนวนไพ่ให้เปิด และไม่มีปุ่มข้าม (ต้องเหลืออย่างน้อย 1 ศาสตร์)
   - ถ้าใช้ร่วมกับศาสตร์อื่นอย่างน้อย 1 ศาสตร์ ระบบสุ่มจำนวนไพ่ให้เปิดทันทีโดยไม่ถามคำถามเพิ่ม
     และมีปุ่ม **ข้ามไพ่ออราเคิล** ให้กด
4. ระบบส่งข้อมูลไปยังเฉพาะ engine ที่เลือกใช้พร้อมกัน (และคำนวณ forecast ที่เลือกไว้ ถ้ามี
   ข้อมูลเกิด)
5. Master Interpreter รับผลดิบจากเอนจินที่เลือกใช้ (และ forecast ถ้ามี) มาสังเคราะห์ — ถ้าเหลือ
   ศาสตร์เดียวจะตีความเจาะลึกศาสตร์นั้นแทนขั้นตอนหาจุดร่วม/ขัดแย้งปกติ
6. แสดงผลคำทำนายฉบับสมบูรณ์ พร้อมรายละเอียดแยกเฉพาะศาสตร์ที่มีข้อมูลจริง (ศาสตร์ที่ข้ามไปจะไม่มี
   tab) และ tab การพยากรณ์ล่วงหน้า (ถ้าเลือกไว้ — มีปุ่มข้ามไปดูทีละแบบ) ให้ผู้ใช้ดูที่มาได้ทั้งหมด
   — ทุกครั้งที่ดูดวงสำเร็จจะบันทึกลงประวัติที่ `/history` อัตโนมัติ
7. หน้าแสดงผลมีช่อง **"ถามเพิ่ม"** — พิมพ์คำถามต่อแล้วกด จะสุ่มไพ่ออราเคิลชุดใหม่ 3-9 ใบให้เปิด
   เมื่อเปิดครบกด "ดูคำทำนาย" ระบบจะสังเคราะห์ต่อเนื่องจากคำทำนายเดิมในเซสชันเดียวกัน โดยให้
   น้ำหนักกับไพ่ชุดใหม่เป็นหลัก (ไม่ใช่ดึงประวัติจาก `/history` มาใช้ — ยังคงกฎ privacy ข้อ 1)
   ทำซ้ำได้เรื่อยๆ และแต่ละรอบก็บันทึกลงประวัติเช่นกัน

## 4. ฟังก์ชันของแต่ละโมดูล

### 4.1 Uranian Engine
- คำนวณตำแหน่งดาว 8 ดวงเสริม (Cupido, Hades, Zeus, Kronos, Apollon, Admetos, Vulcanus, Poseidon) และดาวหลัก (รวม 22 ปัจจัย — ดาวเคราะห์คลาสสิก 10 + ดาวเสริม 8 + Node (True Node) + จุดอาริส + Ascendant/Midheaven)
- คำนวณ midpoint และตำแหน่งบน 90° dial หา planetary picture ทั้ง Type I และ Type II
- จับคู่ configuration กับฐานความหมายใน knowledge base
- **Forecast (ไม่บังคับ, เลือกเปิดทีละแบบที่ฟอร์ม `/reading`)**: Solar Arc Directions, Transit (รวม Station Points, Daily M/A, Transit Axes), Lunar Return, Relocation — ดู `backend/app/modules/uranian/{solar_arc,transit}.py`
- Input: วันเวลาสถานที่เกิด + (ถ้าเลือก forecast) วันที่เป้าหมาย/พิกัดปลายทางสำหรับเทคนิคนั้นๆ
- Output: `EngineResult` (ดู data-schema.md) + `ForecastResponse` ถ้ามีการเลือก forecast

### 4.2 Tarot Engine
- สุ่มจั่วไพ่แบบ fair-random (ไม่ซ้ำใบในกองเดียวกัน)
- รองรับหลาย spread ให้ผู้ใช้เลือกที่หน้า `/reading` (ไพ่ใบเดียว, อดีต-ปัจจุบัน-อนาคต,
  สถานการณ์-อุปสรรค-คำแนะนำ, ความสัมพันธ์ 5 ใบ, กากบาทเซลติก 10 ใบ — แก้ไข 2026-08-14 ดู
  `backend/app/knowledge_base/tarot/spreads.yaml`) — ข้ามศาสตร์นี้ทั้งหมดได้ (ปุ่มข้าม)
- จับคู่ไพ่ + ตำแหน่งใน spread กับความหมายในฐานข้อมูล (อ้างอิงไฟล์ที่มีอยู่แล้วจากโปรเจกต์ Destiny Matrix — ตรวจสอบว่ามีไฟล์อ้างอิงความหมาย 22 เลข/Major Arcana หรือไม่ก่อนสร้างใหม่)
- Output: `EngineResult`

### 4.3 Oracle Engine
- สุ่มจั่วไพ่จากชุดออราเคิลที่กำหนด (deck "ลานลาออราเคิล" — ดู CLAUDE.md หัวข้อ 6)
- **แก้ไข 2026-08-14**: จำนวนใบที่จั่วสุ่มจากระบบเสมอ 3-9 ใบ (ไม่ให้ผู้ใช้เลือกจำนวนเอง) —
  ถ้าเป็นศาสตร์เดียวที่เลือกใช้ (ข้ามยูเรเนียนและทาโรต์ทั้งคู่) ต้องให้ผู้ใช้พิมพ์คำถามก่อนจึงจะ
  สุ่ม/จั่วไพ่ได้ และไม่มีปุ่มข้าม; ถ้าใช้ร่วมกับศาสตร์อื่น สุ่ม/จั่วได้ทันทีโดยไม่ถามคำถาม และมี
  ปุ่มข้ามได้ — ดู `backend/app/core/schema.py` `OracleRequest`
- จับคู่ไพ่กับข้อความ/ธีมในฐานข้อมูล
- Output: `EngineResult`

### 4.4 Master Interpreter (Synthesis Layer)
- รับ `EngineResult` จากเฉพาะ engine ที่ผู้ใช้เลือกใช้ (1-3 ใน 3 — แก้ไข 2026-08-14 ดูข้อ 3) +
  `ForecastResponse` เพิ่มเติมถ้าผู้ใช้เลือกเปิด Solar Arc/Transit/Lunar Return/Relocation ที่ฟอร์ม
  (ไม่บังคับ) + `oracle_question` ถ้าผู้ใช้พิมพ์คำถามไว้ก่อนจั่วไพ่ออราเคิล
- เรียก Gemini API (`gemini-3.1-flash-lite`) พร้อม prompt ที่ระบุกฎตายตัว:
  - ห้ามใส่ bias ส่วนตัว
  - ห้ามอ้างอิงข้อมูลนอกเหนือจากที่ส่งเข้าไปในเซสชันนี้
  - ถ้ามีมากกว่า 1 ศาสตร์: ทำ 3 ขั้นตอน หาจุดร่วม (convergence) → จัดการความขัดแย้ง
    (divergence) → เติมเต็มมุมที่ขาด (complementary); ถ้าเหลือศาสตร์เดียว: ตีความเจาะลึกศาสตร์นั้น
    แทน ไม่ต้องหาจุดร่วม/ขัดแย้ง
  - ถ้ามี forecast ส่งมาด้วย ให้พิจารณาเป็น "ชั้นจังหวะเวลา" เสริม ด้วยหลักการเดียวกัน
  - ถ้ามี oracle_question ส่งมาด้วย ให้ใช้เป็นบริบทหลักในการตีความไพ่ออราเคิลและตอบคำถามนั้น
- Output: คำทำนายฉบับสมบูรณ์ (ทอ forecast เข้าไปด้วยถ้ามี) + คำอธิบายว่าแต่ละศาสตร์สนับสนุนข้อสรุป
  อย่างไร + ตารางดิบของ forecast (ถ้ามี) ให้ผู้ใช้ข้ามไปดูทีละแบบได้ในหน้าผลลัพธ์
- **"ถามเพิ่ม" (แก้ไข 2026-08-14)**: `POST /api/reading/follow-up` — แยก flow ต่างหาก รับคำทำนาย
  เดิมของเซสชันนี้ (ที่ client มีอยู่แล้ว ไม่ใช่ดึงจาก `/history`) + คำถามใหม่ + ไพ่ออราเคิลชุดใหม่
  (สุ่ม 3-9 ใบเหมือนกัน) แล้วสังเคราะห์เป็นคำทำนายต่อเนื่อง โดยให้น้ำหนักไพ่ชุดใหม่เป็นหลัก —
  ดู `synthesize_followup()` ใน `master_interpreter.py`

## 5. Non-functional requirements

- ความถูกต้องของการคำนวณยูเรเนียน/สุ่มไพ่ ต้องมี unit test ครอบคลุม
- Privacy: ไม่เก็บ/ไม่ใช้ browsing history ของผู้ใช้ในการตีความ
- Performance: การเรียก 3 engine ควรทำแบบ concurrent (async) ไม่ใช่ sequential
- Extensibility: เพิ่มชุดไพ่ออราเคิลใหม่ หรือปรับฐานความหมายได้โดยแก้ knowledge base ไม่ต้องแก้โค้ด
